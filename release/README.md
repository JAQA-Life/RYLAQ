# JAQA web — Hostinger upload package

`jaqa-web.zip` is the **static-only** JAQA package for shared hosting (`public_html`): the workspace plus the About, FAQ, Sources, Privacy and 3D Globe info pages, the sitemap and `llms.txt`. The **Global Monitor feeds and the 3D globe need the Node.js server**, so use `jaqa-hostinger.zip` and [`docs/DEPLOY-NODE.md`](../docs/DEPLOY-NODE.md) for the full site. On static hosting the monitor shows publisher links instead of live feeds. It is generated by `npm run build` from `dist/`, and CI checks that it is up to date. Extracted, it looks like this:

```
index.html                       the workspace page (https://jaqa.life/)
.htaccess                        hidden file: security headers, CSP, HTTPS redirect, correct file types
assets/                          the app script, stylesheet and startup-diagnostics script
global-risk/index.html           optional section pages (same app, opening on that section)
finance-risk/index.html
insurance-reinsurance/index.html
procurement-bids/index.html
```

It runs entirely in the visitor's browser. There is no database, PHP, Node.js or build step on the server, and no external fonts or CDNs.

## Upload to Hostinger (File Manager)

1. **Turn off Git deployment.** In hPanel, open your website → **Advanced → Git**, then delete the repository entry or turn off auto-deployment. Otherwise the next Git deploy replaces your upload with a different version.
2. Open **Files → File Manager → `public_html`** and **delete everything in it**, including `default.php`, old `index.html` or `index.php` files, old folders and the old hidden `.htaccess`. Turn on *Show hidden files* to see `.htaccess`.
3. Click **Upload**, choose `jaqa-web.zip`, and wait for it to finish.
4. Right-click `jaqa-web.zip` → **Extract**, and extract into `public_html` itself, not a new sub-folder.
5. Delete `jaqa-web.zip` from `public_html`.
6. Check that `public_html` now directly contains `index.html`, `.htaccess`, the `assets` folder and the four section folders. If they landed in `public_html/jaqa-web/`, move them up one level; otherwise the site shows **403 Forbidden**.
7. In hPanel, make sure **SSL** is active for jaqa.life. Clear the website cache in hPanel, and if the Hostinger CDN is on, purge it too.
8. Open `https://jaqa.life/` and reload with **Ctrl+Shift+R** (on a Mac, Cmd+Shift+R).

Folders should be `755` and files `644` (Hostinger's defaults).

## If something is wrong, the page tells you

The page no longer goes blank. If the app cannot start, a startup screen stays visible, says what went wrong and lists the fixes:

| What you see | What it means | Fix |
|---|---|---|
| **403 Forbidden** | There is no `index.html` directly in `public_html`. | Step 6 above. |
| Startup screen stays, with no specific reason | The browser never ran the app's files: an old `.htaccess` is still there, the `assets` folder is missing, or an old version is being served from cache. | Steps 1, 2, 4 and 7, then a hard reload. |
| "…blocked the app script because of a Content-Security-Policy rule…" | An old `.htaccess`, or a server, cache or CDN rule, is overriding the new one. | Delete the old `.htaccess` (step 2), re-extract, clear caches (step 7). |
| "…could not be loaded (assets/…)" | The `assets` folder or one of its files is missing. | Re-extract the whole zip into `public_html`. |

## Quick check after upload

- `https://jaqa.life/` shows the Situation Room: header, search bar, globe and panels.
- `https://jaqa.life/.htaccess` returns 403.
- In the browser DevTools **Console**, there are no red errors on load.

To update later, download the new `jaqa-web.zip` and repeat steps 2–8.
